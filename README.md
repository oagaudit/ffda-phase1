# FFDA — ระบบวิเคราะห์วินัยการเงินการคลังขององค์กรปกครองส่วนท้องถิ่น · เฟส 1 (Dashboard)

แดชบอร์ดแบบ interactive (คล้าย Power BI) เจาะลึกจาก **ประเทศ → ภูมิภาค → จังหวัด → อำเภอ → อปท.**
มี 3 โหมด (ภาพรวม / ประชาชน / เจ้าหน้าที่ สตง.), สร้างมุมมองเองได้ และนำเข้า Excel ผลการประเมินได้ทุกปี (2569 → 2570 → ...)
**รองรับข้อคำถามที่เพิ่ม/ลด/เปลี่ยนในปีถัดไป** ด้วยรหัสตัวชี้วัดถาวรและขั้นตอนอนุมัติโครงสร้างแบบประเมิน

> เฟส 2 (ML / Generative AI) แยกพัฒนาภายหลัง — โครงสร้างข้อมูลเฟส 1 เตรียมไว้ให้แล้ว (ผล ML เก็บแยกตาราง ไม่แก้ตารางผลประเมิน; ตัวแปรของโมเดลอ้างรหัสตัวชี้วัด ไม่อ้างเลขข้อ)

**ไม่มีหน้า login** — แยกเป็น 2 เว็บ: เว็บสาธารณะ (อินเทอร์เน็ต: ภาพรวม/ประชาชน) และเว็บเจ้าหน้าที่ (intranet: SSO ด้วยบัญชี AD ผ่าน IIS)
ใช้โค้ดชุดเดียวกัน กำหนดด้วย `FFDA_MODE` (backend) และ `npm run build:public` / `build:staff` (frontend) — ดู `deploy/windows/README-deploy.md`


## 1) เตรียมเครื่อง MacBook Air M3 (ทำครั้งเดียว)

เปิดแอป **Terminal** แล้วพิมพ์ทีละบรรทัด

```bash
# 1.1 ติดตั้ง Homebrew (ตัวจัดการโปรแกรมบน Mac) — ถ้ามีแล้วข้ามได้
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
# ทำตามข้อความท้ายการติดตั้ง (คำสั่ง eval ... เพื่อเพิ่ม brew เข้า PATH)

# 1.2 ติดตั้ง Python 3.12, Node.js 20 LTS และ Git
brew install python@3.12 node@20 git
brew link --overwrite node@20

# 1.3 (แนะนำ) ติดตั้ง PostgreSQL 16 ให้เหมือนเครื่องจริง — ช่วงแรกจะใช้ SQLite ก็ได้ (ข้ามข้อนี้)
brew install postgresql@16
brew services start postgresql@16
createuser -s ffda && createdb -O ffda ffda
psql -d ffda -c "ALTER USER ffda WITH PASSWORD 'ffda-dev';"

# ตรวจเวอร์ชัน
python3.12 --version   # 3.12.x
node -v                # v20.x
```

ส่วนเสริม VS Code ที่แนะนำ: **Python**, **Pylance**, **ESLint**, **Prettier**, **Thunder Client** (ทดสอบ API)

## 2) รันระบบบนเครื่อง (ช่วงพัฒนา)

แตกไฟล์โปรเจกต์ แล้ว **File → Open Folder** เลือกโฟลเดอร์ `ffda-dashboard` ใน VS Code
เปิด Terminal ใน VS Code (**Ctrl + `**) — ต้องเปิด 2 แท็บ (backend / frontend)

### แท็บที่ 1: backend (Python)
```bash
cd backend
python3.12 -m venv .venv            # สร้างสภาพแวดล้อมแยก (ครั้งแรกครั้งเดียว)
source .venv/bin/activate           # ทุกครั้งที่เปิด Terminal ใหม่
pip install -r requirements.txt     # ครั้งแรก / เมื่อ requirements เปลี่ยน
cp .env.example .env                # ครั้งแรก (FFDA_MODE=dev สลับดูได้ทุกโหมด, ผู้ใช้จำลอง DEV_USER)

# นำเข้าข้อมูลปี 2569 (ครั้งแรก) — ใช้ไฟล์ "survey_analyst ดิบ.xlsx"
python -m scripts.import_excel --year 2569 --file "/path/to/survey_analyst ดิบ.xlsx" --publish

uvicorn app.main:app --reload --port 8000
```
เปิด http://localhost:8000/docs เพื่อดูเอกสาร API อัตโนมัติ

### แท็บที่ 2: frontend (Node.js)
```bash
cd frontend
npm install        # ครั้งแรก
npm run dev        # เปิด http://localhost:5173
```
แก้โค้ดแล้วหน้าเว็บรีเฟรชเองทันที — ช่วง dev ใช้ปุ่มสลับ “ภาพรวม / ประชาชน / เจ้าหน้าที่ สตง.” มุมขวาบน (ไม่มี login)

### ทดสอบให้เหมือนเครื่องจริง
```bash
# backend โหมด public (ไม่มี API เจ้าหน้าที่) / โหมด staff (ต้องมี header SSO จาก IIS)
FFDA_MODE=public python -m tests.test_smoke
FFDA_MODE=staff  python -m tests.test_smoke
# frontend 2 ชุด
npm run build:public    # → dist-public  (ไม่มีโค้ดหน้าเจ้าหน้าที่ติดไปเลย)
npm run build:staff     # → dist-staff
```

### ทดสอบ
```bash
cd backend && source .venv/bin/activate
python -m tests.test_smoke       # ทดสอบ API ทุกโหมด รวมถึงการปิดกั้นข้อมูลตามสิทธิ์
```

## 3) การนำเข้าข้อมูลรายปี

| ขั้น | ทำอะไร | ที่ไหน |
|---|---|---|
| 1 | เลือกปี (2569) และไฟล์ Excel | เมนู **นำเข้าข้อมูล** (admin) |
| 2 | กด **ตรวจสอบไฟล์** — ระบบตรวจคอลัมน์ รหัส อปท. แถวซ้ำ และความถูกต้องของคะแนน โดยยังไม่บันทึก | |
| 3 | กด **นำเข้า** — ข้อมูลเข้าเป็นสถานะ **ร่าง** เห็นเฉพาะเจ้าหน้าที่ ระบบคำนวณระดับผลอัตโนมัติ | |
| 4 | ตรวจทานบนแดชบอร์ด | |
| 5 | กด **เผยแพร่** — โหมดภาพรวม/ประชาชนจึงเห็นปีนี้ | |

- **ปี 2570 ขึ้นไป**: ต้องอนุมัติ **โครงสร้างแบบประเมิน** ของปีนั้นก่อน (หัวข้อ 3.1) แล้วทำขั้นตอนเดิม — ข้อมูลปีก่อนยังอยู่ครบ
- **นำเข้าปีเดิมซ้ำ** = แทนที่ข้อมูลทั้งปี (แก้ไฟล์แล้วนำเข้าใหม่ได้เสมอ) ไฟล์ต้นฉบับทุกไฟล์เก็บไว้ใน `backend/uploads/<ปี>/`
- ต้องการทดสอบระบบหลายปีก่อนได้ข้อมูลจริง: `python -m scripts.make_demo_year --src <ไฟล์2569> --out DEMO_2570.xlsx --change-questions` (ข้อมูลจำลอง ห้ามเผยแพร่ · `--change-questions` จำลองการยกเลิก/เพิ่ม/เปลี่ยนข้อคำถาม)

### 3.1) เมื่อข้อคำถามปีใหม่ เพิ่ม / ลด / เปลี่ยน (เมนู **โครงสร้างแบบประเมิน**)

ทุกข้อมี **รหัสตัวชี้วัดถาวร** (`REV-01`…`REV-10` รายได้, `EXP-` รายจ่าย, `PRC-` พัสดุ, `ACC-` บัญชี) ไม่ผูกกับเลขข้อ
→ ปีหน้าเลขข้อเลื่อน แนวโน้มรายข้อยังเทียบถูกตัว · คะแนนรวม/รายด้านคิดเป็น % ของคะแนนเต็มของปีนั้น จึงเทียบข้ามปีได้แม้จำนวนข้อเปลี่ยน

| ขั้น | ทำอะไร |
|---|---|
| 1 | อัปโหลดไฟล์ผลประเมินปีใหม่ (ระบบอ่านเฉพาะหัวคอลัมน์ ยังไม่นำเข้าผล) |
| 2 | ระบบเทียบข้อความคำถามกับปีก่อน (ตัดเลขปี พ.ศ. ออกก่อนเทียบ) แล้วจัดประเภทแต่ละข้อ: **เหมือนเดิม · ปรับถ้อยคำ (เทียบได้) · เปลี่ยนสาระ (ตัดเส้นแนวโน้ม) · ข้อใหม่ (รหัสใหม่) · ยกเลิก** |
| 3 | ผู้ดูแลตรวจข้อที่มีเครื่องหมาย ⚠ (แก้รหัส/ประเภท/ชื่อย่อ/คะแนนเต็ม) เลือกคอลัมน์หลักถ้าชื่อเปลี่ยน และใส่หมายเหตุอ้างอิงมติที่ประชุม |
| 4 | **อนุมัติ** (บันทึกผู้อนุมัติ/เวลา) → นำเข้าผลประเมินได้ · นำเข้าไม่ได้ถ้ายังไม่อนุมัติ (กันไฟล์ที่ข้อเปลี่ยนโดยไม่รู้ตัว) |

หน้าเดียวกันมี **ตารางเทียบข้อคำถามข้ามปี (crosswalk)** · หน้า **วิเคราะห์รายข้อ** แสดงสิ่งที่เปลี่ยนในปีที่เลือก และกราฟแนวโน้มรายตัวชี้วัดข้ามปี
ทำผ่าน command line ได้: `python -m scripts.questionnaire propose --year 2570 --file <ไฟล์>` → `approve --year 2570` → `crosswalk`
ข้อจำกัดที่ทราบ: กรอบ 4 ด้านคงที่ (เพิ่มด้านที่ 5 ต้องแก้โครงสร้างตาราง) · ข้อ 1–8 ฉบับ อบจ. ใช้รหัสเดียวกับฉบับ อบต./เทศบาลในตำแหน่งเดียวกัน
